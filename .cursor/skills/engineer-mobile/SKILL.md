# Mobile Engineer

## Scope

Own the Capacitor native shell wrapping the trefolio web app for iOS and Android, including native project configuration, plugin bridges, emulation workflows, and store submissions.

## Architecture

The native apps are thin Capacitor shells that load the hosted web app (`https://trefolio.app`) in a native WebView. All business logic, SSR, API routes, and auth remain on the server — the native layer provides splash screen, status bar, push notifications, and hardware back button handling.

```
┌──────────────────────────────────┐
│  Native Shell (Capacitor)        │
│  ┌────────────┐ ┌──────────────┐ │
```

## Quick-Start: Launch Emulation

### iOS Simulator (macOS + Xcode required)

```bash
# Terminal 1: start the dev server
npm run dev

# Terminal 2: open in iOS Simulator
npm run cap:ios
# Xcode opens → select a simulator (e.g. iPhone 16 Pro) → Cmd+R to run

# OR: headless (no Xcode UI)
npm run cap:run:ios
# Capacitor picks the default simulator automatically
```

iOS Simulator can reach `localhost` directly — no host mapping needed.

### Android Emulator (Android Studio required)

```bash
# Terminal 1: start the dev server
npm run dev

# Terminal 2: open in Android Emulator
npm run cap:android
# Android Studio opens → select AVD → Shift+F10 to run

# OR: headless (no Android Studio UI)
npm run cap:run:android
# Requires an AVD already created via Android Studio > Tools > Device Manager
```

Android Emulator uses `10.0.2.2` to reach the host machine's `localhost`. The `cap:android` script handles this automatically.

### Syncing After Config Changes

```bash
# After changing capacitor.config.ts:
npx cap copy          # copies config to native projects
npx cap sync          # copy + update native plugins

# For production URL:
npm run cap:prod      # copies with production URL
```

## npm Scripts

| Script | Purpose |
|--------|---------|
| `cap:dev` | Copy config with `localhost:3000` as server URL |
| `cap:ios` | Copy local config + open Xcode |
| `cap:android` | Copy local config (10.0.2.2) + open Android Studio |
| `cap:prod` | Copy config with production URL |
| `cap:run:ios` | Copy + run directly on iOS Simulator (headless) |
| `cap:run:android` | Copy + run directly on Android Emulator (headless) |

## Capacitor Config Rules

- **Server URL toggle**: use `CAPACITOR_SERVER_URL` env var; never hardcode `localhost` in committed config
- **Production default**: config falls back to `https://trefolio.app` when no env var is set
- **cleartext**: must be `false` in production; only `true` when CAPACITOR_SERVER_URL starts with `http://`
- **webDir**: set to `public` (Capacitor requires a webDir even in hosted mode; the actual content comes from the server URL)
- **Plugin config**: splash screen and status bar are configured in `capacitor.config.ts` under `plugins`

## Native Plugin Conventions

### Adding a Plugin

1. Install: `npm install @capacitor/plugin-name`
2. Sync: `npx cap sync`
3. Bridge: use dynamic `import()` in a component, gated by `isNativePlatform()`
4. Never import Capacitor plugins at the top level — always dynamic import to avoid breaking the web build

### Bridge Pattern

```typescript
import { isNativePlatform } from "@/lib/capacitor";

useEffect(() => {
  if (!isNativePlatform()) return;
  async function init() {
    const { PluginName } = await import("@capacitor/plugin-name");
    // use plugin...
  }
  init();
}, []);
```

## Platform Quirks

| Quirk | iOS | Android |
|-------|-----|---------|
| localhost access | `localhost` works directly | Must use `10.0.2.2` |
| Cookie persistence | WKWebView persists cookies | WebView persists cookies |
| Back button | Swipe-back gesture (iOS native) | Hardware back → `CapacitorBridge` handles via `App.addListener("backButton")` |
| Safe areas | `env(safe-area-inset-*)` works in WKWebView | `env(safe-area-inset-*)` works in modern Android WebView |
| Status bar | Controlled via `@capacitor/status-bar` | Background color settable; style via StatusBar plugin |
| Web push | Supported in WKWebView (iOS 16.4+) | Supported in Android WebView |

## Testing Checklist

```md
Mobile Change Checklist
- [ ] Auth flow: login, signup, OAuth redirects work inside WebView
- [ ] Cookie persistence: session survives app backgrounding and relaunch
- [ ] Navigation: hardware back button (Android), swipe-back (iOS)
- [ ] Safe areas: content not obscured by notch, home indicator, or status bar
- [ ] Push notifications: permission prompt appears, notifications received
- [ ] Keyboard: input fields scroll into view, keyboard doesn't obscure content
- [ ] Orientation: landscape/portrait transitions work correctly
- [ ] Splash screen: displays briefly with trefolio branding, then loads app
- [ ] Status bar: dark style, matches app header color
- [ ] InstallPrompt: hidden when running in native context
```
